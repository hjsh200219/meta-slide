# 슬라이드 원칙 — 「전략적 Presentation 기법」 요약

출처: 사내 공유 Keynote PDF `전략적PPT기법0820_vfinal.key.pdf`(373쪽, Slack EDB 2026-10-21 공유). 쪽 번호는 그 PDF 기준.
사내 참고용 요약이다. 이 파일과 원본 내용은 Jev 등 외부 API 로 보내지 않는다.

## 출발점

- 잘 만든 문서 = **프리젠터가 발표하기 가장 편한 상태**다(p22). 사람마다 취향이 다르니 프리젠터의 성향(썰을 푸는 쪽인지, 꽉 차 보여야 안심하는 쪽인지, 도식을 원하는지, 글자 크기 취향)을 먼저 파악한다(p23, p280).
- PPT 는 문서 디자인이 아니라 **생각의 디자인**이다(p19). 보편 원칙은 두 가지뿐이다(p25).

## 원칙 ① 잘 보여야 한다 (p26~p139)

- 잘 보인다는 것은 글씨를 크게 쓰는 것이 아니다. 작게 써도 잘 보인다(p28~p30).
- 잘 보여야 하는 것은 **메시지**다. 그림·서체·아이콘·바탕(빼다)·장식은 보조다(p31).
- 잘 보이는 문서의 진실은 **凸凹 — 강약 조절**이다(p32~p34).

일하는 순서(p74~p83, p134):

1. **프리젠터 의도 파악** — 만들기 전에 읽고, 모르면 묻는다. 「이 문서의 핵심이 무엇인가?」(p75)
2. **전체 구도 잡기** — 기획서 흐름을 크게 나누고 **간지**로 표시한다(p76~p77).
3. **1 slide, 1 idea** — 핵심만 강조하고 나머지는 박스 처리한다(p79).
   - 두 줄이면 핵심 줄을 크고 굵게(Large & Bold), 한 줄 안에서도 핵심 단어만 굵게 또는 색으로(p80).
4. **핵심이 둘 이상이면 도식화**한다(p81).
5. **마지막에 요약**한다. 요약이 안 되면 시놉에 빈 곳이 있거나 이해를 못 한 것이다(p82).

- 자기 생각을 정리할 때도 같다. PPT 에 바로 올리며 생각하지 말고 시놉을 먼저 쓴다 — 넘어가기 전 점검: 팔아야 할 개념이 명쾌한가 · 요약이 되는가 · 스토리 구성이 되는가(p85~p86).
- **확인법: 헤드라인만 읽어서 스토리가 되면 OK**(p94).
- 같은 내용이라도 구도·강약·도식만 바꾸면 전혀 다른 문서가 된다(p35~p72 «두 원고 틀린 점 찾기»).
- 시간이 없거나 내부 회의용이어도 강약 조절은 지킨다 — 흰 바탕에 검은 글씨, 클 건 크고 작을 건 작게, 중간 핵심 페이지는 바탕색을 바꾸고, 가능하면 도식화(p137~p139).

## 원칙 ② 기왕이면 다홍치마 (p160~p232)

- **바탕(템플릿)은 단색 + 포인트**: 튀지 않게, 메시지를 가리지 않게, 너무 허름하지 않게만 포인트를 더한다(p165~p172). 브랜드 시그니처 색이 있으면 적절히 톤 다운해 쓴다(p171).
- **간지는 같은 레이아웃에 색만 바꾼다**(p173~p174).
- 이미지는 고품질 배경용(검색어 «wallpaper» 류)으로 찾는다(p175~p183).
- 안 예뻐 보이는 이유는 대부분 **자간**이다. 너무 좁아도 문제지만 너무 넓으면 없어 보인다(p184~p187).
- **서체**: 정식 라이선스나 공개 서체를 쓴다(강의자는 삼성 긴고딕). **굴림체·바탕체는 쓰지 않는다**(p188). 흔한 서체라도 자간을 좁히고 강조만 줘도 없어 보이지 않는다(p189).
- 두 줄이면 한 줄을 키우고, 세 줄이면 점층(아래로 갈수록 크게 — 가장 중요한 것이 맨 아래)으로(p190~p191).
- **색**: 흑백만으로도 충분하다. 쓴다면 포인트 한 색(파랑·주황·핫핑크 등 — 맥락에 맞게). 흰 바탕일 때 색 쓰기가 가장 어렵다 — 아주 제한적으로(p192~p195).
- **먼저 흑백으로 만들고 그 뒤에 색을 입힌다**(p196).
- 허전한 페이지는 아이콘·실루엣·뒤에 깐 그림으로 채운다(p197~p207).
- 복잡한 내용은 프리젠터에게 단순한 구성을 요청한다. 그래도 어쩔 수 없으면 원칙을 어기고 최선을 다한다(p211~p213).
- **표는 가능하면 그래프로, 안 되면 선을 최소화**한다(p227~p228).
- 그래프는 기본 차트 기능보다 새로 그리는 편이 보기 좋다(p231~p232).

## 마무리 순서 (p279)

잘 보이게가 먼저다 → 꼼꼼히 읽어 의도를 파악하고 강약 조절을 염두에 둔다 → **바탕·간지로 큰 틀** → **각 페이지 헤드라인을 먼저 잡아 강조** → 복잡한 내용 **도식화** → **요약** → 그다음 디테일(이미지·아이콘·서체·색·표·그래프).

## meta-slide 가 코드로 지키는 것

| 원칙 | 어디서 |
|---|---|
| 간지로 구도 · 1 slide 1 idea · 헤드라인만 읽어 스토리 · 마지막 요약 · 표→그래프 | `slide.py outline` 점검 |
| 한 장 한 메시지 · 헤드라인이 메시지인가(라벨이 아닌가) | `slide.py outline --jev` (Jev noul — 외부 전송) |
| 단색 + 포인트 · 굴림/바탕 금지 · 서체 짝 | `slide.py pick` (Jev 가 템플릿·서체 선택, 서체 목록에 굴림·바탕 없음) |
| 자간(넓은 자간 줄이기) · 한글 줄간격 · 단어 중간 줄바꿈 금지 | `slide.py new` 가 넣는 `meta-slide.css`·`meta-slide.js` |
| 넘침·대체 서체·화면 점검 | `slide.py shots` (Playwright 캡처 + 자동 검사) |
