```bash
S="<이 스킬 폴더>/slide.py"     # 스킬을 부르면 표시되는 Base directory
python3 $S templates | layouts <템플릿> | colors [--scheme dark] | fonts | ig [계열|인포그래픽]   # 목록
python3 $S synopsis [전략]                                   # 시놉시스 전략 목록 · 그 전략의 장 구성·규칙·예시
python3 $S synopsis 원고.md [--skeleton 개요.md]             # Jev ⓪ — 원고에 맞는 전략(후보 3) + 장 구성 · 빈 개요
python3 $S outline 개요.md                                   # 원칙 점검 + 헤드라인만 읽기
python3 $S pick 개요.md                                      # Jev ①④⑤ — 템플릿(후보 3)·색 체계·서체
python3 $S new 덱폴더 --template <id> --color <id|template> --title-font <id> --body-font <id> [--brand '#hex']
python3 $S outline 개요.md --template <id> --jev            # Jev ②③ + 장마다 한 메시지·헤드라인·레이아웃 → 템플릿 몇 번 장
python3 $S ig <인포그래픽>                                    # 그 인포그래픽의 문법 예시(장에 붙일 조각)
python3 $S diagram [계열]                                    # AntV 에 없는 계열 — 장표 규약 + 배치 문법 + 수치 선언(직접 SVG 로 그림)
python3 $S shots 덱폴더/deck.html --pdf                      # 장마다 캡처 + 자동 검사 + sheet.png + deck.pdf
python3 $S record 덱폴더 --series <이름> --title <제목>       # 이력 — 다음 같은 시리즈는 같은 템플릿·색·서체
python3 $S history                                           # 이력 보기
python3 $S                                                   # 인자 없이 — 로컬 갤러리(아래)
python3 <이 스킬 폴더>/setup.py [--check|--force|--forget]   # Jev 키 저장(아래)
```

Windows 는 `python3` 대신 `python`(또는 `py`)으로 부른다. 경로·인코딩·키 저장은 OS 마다 맞춰 둬서 명령은 같다.

### `/meta-slide` 를 인자 없이 — 로컬 갤러리

- `python3 $S` 를 **백그라운드로** 실행하고(서버가 계속 떠 있어야 한다) 찍힌 주소를 알린다. `http://127.0.0.1:8766/` — 탭 다섯: 시놉시스 50(장 구성·규칙·같은 주제 예시) · 템플릿 230(표지 썸네일·바탕·출처·장 구성 거르기, 누르면 장 구성·색·원본 서체·「한글 서체 적용해 열기」·「원본 열기」·만들기 명령) · 인포그래픽 265(한글 예시로 실제 렌더) · 색 체계 161 · 한글 서체 17. 끄기 Ctrl-C · `--port` · `--no-open`.
- 페이지는 매번 `~/.cache/meta-slide/gallery/` 에 다시 만든다. 「한글 서체 적용해 열기」는 처음 누를 때 `new`(기본 서체 Pretendard)로 `~/.cache/meta-slide/preview/<id>/` 를 만든다.
- **`--local`**(사용자가 SSH 로 이 컴퓨터에 붙어 쓸 때 — 「내 PC 에서」·「로컬로」): `python3 $S --local` 을 백그라운드로 띄우면 127.0.0.1 과 이 컴퓨터의 Tailscale 주소에 함께 연다. **같은 Tailscale 계정 기기만** 들어오고(다른 사람 기기 403, Host 머리글 검사), 2시간 요청이 없으면 스스로 꺼진다. 출력 끝의 `LOCAL_URL=` 을 사용자 PC 크롬에서 연다 — claude-in-chrome `navigate(LOCAL_URL)`. 여러 브라우저가 붙어 있으면 `LOCAL_BROWSER=`(짝지은 PC 크롬 deviceId)로 `select_browser` 한 뒤 연다. 그 브라우저가 연결돼 있지 않으면 **다른 브라우저에 열지 말고** `LOCAL_URL` 을 링크로 답한다(이 컴퓨터의 브라우저에 열면 사용자가 못 본다). 포트를 다른 프로그램이 쓰면 다음 포트로 옮겨 그 주소를 찍는다. Tailscale 이 없으면 `--local` 은 열리지 않는다(오류 문구 그대로 알린다).

### Jev 키 — `setup.py`(`/meta-slide:setup`)

- `pick`·`outline --jev` 는 Jev API 키가 있어야 한다. 키를 읽는 순서: 환경변수 `JEV_API_KEY` → `setup.py` 가 저장한 곳(macOS 키체인 서비스 `typesafe-jev` · Windows 자격 증명 관리자 `typesafe-jev/JEV_API_KEY` · 그 밖 `~/.config/typesafe-jev/key` 0600, Windows 에서 자격 증명 관리자를 못 쓰면 `%APPDATA%\typesafe-jev\key`) → `~/workspace/.env`. meta-motion 과 같은 저장소라 한 번 저장하면 둘 다 된다.
- 키가 없다는 오류(`JEV_API_KEY 없음`)가 나면 `/meta-slide:setup` 을 안내하거나 실행한다. **키를 채팅으로 받지 않는다** — `setup.py` 가 터미널이면 화면에 안 찍히는 입력, 아니면 OS 입력 창으로 받고, Jev 에 작은 질문 1번으로 확인한 뒤에만 저장한다. SSH 로 붙어 있으면 입력 창이 원격 화면에 떠서 못 보므로 사용자가 SSH 터미널에서 `python3 <이 스킬 폴더>/setup.py` 를 직접 실행한다.
- 키 없이도 `--no-jev`(기본 템플릿·색·서체)로 덱을 만들 수 있다.

`synopsis` 는 원고(6천 자 — 앞 3/4 + 끝 1/4), `pick`·`outline --jev` 는 개요 글을 Jev(api.typesafe.ai)로 보낸다. 개요 내용(사내 수치·실적 등)을 이유로 Jev 를 건너뛰지 않는다 — 같은 내용이 이미 Claude 로 가므로 Jev 만 막을 이유가 없다(2026-10-22 사용자 지시). `--no-jev` 는 키가 없거나 사용자가 Jev 없이 하라고 할 때만 쓴다(기본값: 어두운 `broadside`, `--scheme light` → `blue-professional`). `data/principles.md` 원문은 Jev 로 보내지 않는다(고르는 데 필요 없다). 인포그래픽은 장 안에서 로컬로만 렌더한다 — `meta-slide-ig.js` 가 AntV 기본 동작(아이콘을 weavefox.cn 검색 API 로, 서체를 antgroup CDN 에서)을 막고 로컬 Tabler 아이콘·덱 서체를 쓴다.

## 순서 — 원칙의 「일하는 순서」 + 다섯 가지 고르기

0. **원칙**: `data/principles.md` 를 읽는다.
1. **프리젠터 의도 파악**(p75). 누가 발표하고 누가 듣는지, 이 문서의 핵심 한 문장이 무엇인지 정한다. 요청에서 알 수 없고 추정하면 위험할 때만 묻는다. 발표자 성향(썰 풀기형·꽉 찬 자료형·도식 선호·글자 크기 취향)을 알면 반영한다(p23).
2. **시놉시스 전략 고르기**(원고·스크립트·대본·메모가 있을 때 — 2026-10-22 사용자 「스크립트를 시놉시스로, 시놉시스로 슬라이드를」). `python3 $S synopsis 원고.md --skeleton 개요.md` — Jev 가 전략 50종(컨설팅 피라미드·광고 대행사 PT·애플 키노트·투자 피치·BLUF 보고·B2B 제안·교육·연구 발표·스파크라인·TED·잡스 졸업 연설·로슬링·MLK·간츠·윈스턴 「How to Speak」·Presentation Zen·카네기·세바시 …) 중 원고의 목적·청중·재료·형식에 맞는 것을 고른다(choice, 후보 3 + 확신). 우선순위: 사용자 지정 `--synopsis` > 개요 머리말 `synopsis:` > 같은 시리즈 이력 > Jev > 기본값 `bluf-report`.
   - 고른 전략·후보 2개·확신을 한 줄씩 보여 주고 다른 지시가 없으면 그대로 진행한다. 확신이 0.5 미만이면 후보 둘의 장 구성을 비교해 원고에 맞는 쪽을 직접 고르고 이유를 적는다(`python3 $S synopsis <전략>` 으로 비교).
   - **원고를 개요로 옮기는 것은 Claude 가 한다**(Jev 는 고르기만). 전략의 단계(비트) 순서·꼭 있어야 할 단계(*)·헤드라인 문체·장 규칙을 따르고, 원고에 없는 사실은 지어내지 않는다 — 단계에 넣을 재료가 원고에 없으면 그 장을 빼고 보고에 「원고에 ○○ 없음」으로 적는다. 원고의 긴 설명은 노트(`>`)로.
   - 개요 머리말에 `synopsis: <전략>` 을 남긴다 — `outline`·`pick`·`new`·`record` 가 그 전략을 이어받는다(점검 기준 · 템플릿 고르기 · 이력).
   - **사례·실제 화면을 덜어 내지 않는다**(2026-10-23 사용자 「너무 압축, 실제 예시 화면이나 사례가 중요」·「사례는 실제 이미지나 업무/구현 flow 가 있어야」): 원고에 실제 화면·사례가 있으면 장 수를 줄이려고 빼지 않는다. 사례를 보여 주는 발표면 전략과 무관하게 사례마다 업무·구현 흐름도(행위자 → 동작 → 결과)와 **실제 화면을 한 장 이상** 둔다 — 흐름도만으로는 부족하다(같은 날 「사례에 실제 화면을 넣을 게 많잖아 — Slack 초안 작성해 버튼 누르는 것, CS 자동 처리 댓글」). 실제 화면은 원본 서비스(Slack·GitHub·터미널·사내 사이트)를 로그인된 브라우저로 2배 해상도로 찍어 메시지·상자 단위로 자르고, 생성 일러스트로 대신하지 않는다(「일러스트가 이해에 큰 도움이 안 된다」). 다른 부서가 모르는 사내 용어(예: KB 「카드」)는 실제 화면을 보여 주며 한 줄로 풀어 쓴다.
   - 전략 목록·예시는 갤러리 「시놉시스」 탭에서도 본다. 모든 전략의 예시가 같은 주제(약국 재고 자동 발주)라 차이가 바로 보인다.
3. **시놉(개요) 먼저**(p85~86) — PPT 에 바로 올리며 생각하지 않는다. `개요.md`:
   ```markdown
   ---
   title: 발표 제목
   subtitle: 부제
   presenter: 발표자 · 의도(이 문서의 핵심 한 문장)
   audience: 듣는 사람
   date: 2026-10-21
   synopsis: consulting-pyramid   # 2단계에서 고른 전략(원고 없이 시작하면 생략 가능)
   ---
   # 간지(장) 제목
   ## 헤드라인 — 이 장의 결론을 문장으로
   - 근거(3~5개, 한 줄에 한 생각)
   > 발표자 노트(말로 할 것)
   ## 마지막 요약 장 {summary}
   ```
   헤드라인은 이름표(「현황」「배경」)가 아니라 결론 문장. 장 태그 `{statement}` `{diagram}` `{compare}` `{number}` `{chart}` `{quote}` `{timeline}` `{summary}` … 로 레이아웃을 직접 정할 수 있다(`slide.py` 의 `LAYOUTS`).
4. **`outline` 점검**을 고칠 것이 없을 때까지 — 간지(8장 이상이면 2개 이상) · 헤드라인 길이 · 근거 5개 이하 · 표→그래프 · 끝 요약. 머리말에 `synopsis:` 가 있으면 길이·근거 수·본문 양·요약 위치(앞/끝/없음)·사진 장 비율을 그 전략 기준으로 본다(키노트 헤드라인 20자·근거 1개, BLUF·컨설팅은 결론이 첫 세 장 안 …). 「헤드라인만 읽기」가 그대로 이야기가 되는지 직접 읽는다(p94).
5. **`pick` — ① 템플릿 → ④ 색 체계 → ⑤ 서체**. 템플릿이 200개를 넘으면 묶음 예선 → 결승으로 고른다. 색·서체는 고른 템플릿(분위기·영문 서체 성격·바탕 밝기)을 보여 주고 고른다. 색은 템플릿과 같은 밝기의 체계 중 글자 대비 7 이상·주색 대비 3 이상만 후보이고, 「템플릿 원래 색 유지」도 후보다. 우선순위: 사용자 지정(`--template`·`--color`·`--title-font`·`--body-font`) > 같은 시리즈 이력(`--series`) > Jev > 기본값. 사용자에게 고른 템플릿·후보 2개·색·서체를 한 줄씩 보여 주고, 다른 지시가 없으면 그대로 진행한다.
6. **`new`** — 템플릿 폴더를 복사해 `deck.html` 을 만든다.
   - 색(④): `--color <id>` 면 HTML·CSS 의 색 값을 역할대로 바꾼다 — 무채색은 바탕↔글자 사이 위치를 지켜 체계의 바탕·글자 색 사이로, 유채색은 많이 쓰인 순서대로 주색·강조·보조로(원래 명도는 지킨다). `--brand '#hex'` 는 포인트 색 하나만 브랜드 색(12% 톤 다운, p171)으로.
   - 서체(⑤): 모든 `font-family`·`--*font*` 선언(HTML 과 복사된 CSS 파일)의 템플릿 웹 서체 뒤·시스템 서체 앞에 한글 서체를 끼운다(제목 계열 → 제목 서체, 나머지 → 본문 서체). 영문은 템플릿 서체, 한글은 고른 서체로 그려진다.
   - `meta-slide.css`(단어 중간 줄바꿈 금지 `keep-all` · deck-stage 시스템 서체 덮기 · 인포그래픽 색 `--ms-ig-1..4`) · `meta-slide.js`(한글 글자의 넓은 자간 0.06em 초과 → 0.01em, 좁은 줄간격 → 1.18 — p187 · 40px 이상 한글 제목이 장 밖으로 넘치거나 아래 글을 밀어내면 글자 크기를 최소 55~70%까지 줄임 `data-ms-fit`) · `infographics/` 런타임을 붙인다.
7. **`outline --template <id> --jev` — ② ③ + 장 점검**. 장마다 Jev 가 한 장 한 메시지인가·헤드라인이 메시지인가(noul), 레이아웃(그 템플릿에 있는 종류만, choice)을 판정하고, **② 인포그래픽으로 보여 주면 더 잘 전달되는가**(noul, 0.6 이상 — 표지·간지·한 문장·인용·요약·마무리·숫자 장은 제외: 원칙상 글이 주인공) → **③ 계열**(순서·깔때기·피라미드·순환·타임라인·로드맵·격자·2자 비교·SWOT·사분면·트리·마인드맵·흐름도·그래프 …)(가로 장에서 작게 그려지는 세로로 긴 모양 — `catalog.json` 의 실측 `aspect` 1.3 미만 — 은 후보에서 뺀다) → **그 계열 안 모양**(덱 스타일을 같이 보여 주고 choice)을 고른다. 계열 후보에는 AntV 에 없는 **직접 그린 도식** 10계열(`draw:` — 벤·폭포·꺾은선·기울기·레이더·트리맵·간트·레이어·피시본·히트맵)이 같이 들어간다. 출력: 템플릿 몇 번 장을 복제할지 + 인포그래픽을 넣을 장과 이름 + 「직접 그린 도식」 장과 계열. 시놉시스 전략이 있으면 장마다 **그 전략의 어느 단계인가**(choice — 장 위치·앞뒤 헤드라인을 같이 넘긴다)도 판정해 꼭 있어야 할 단계가 빠졌는지(`beat-missing`)·처음 나오는 순서가 전략과 다른지(`beat-order`)를 알리고, 전략의 헤드라인 문체로 「이름표 헤드라인」을 판정하며(사진·간지 단계의 장면·제품명 헤드라인은 경고하지 않음), 인포그래픽 기준값도 전략 값(키노트 0.85 · 컨설팅 0.5 …)을 쓴다.
8. **덱 채우기**(Claude 가 직접 편집) — 대응표대로 템플릿 장(`<section>`·`.slide`)을 복제·배치하고 글을 바꾼 뒤 쓰지 않는 장은 지운다.
   - **지킨다**: 서체 선언·`:root` 변수 구조·격자·장 클래스·장식·내비게이션 런타임. 템플릿에 없는 레이아웃이 필요하면 같은 서체·색·장식 어휘로 새로 그린다.
   - **바꾼다**: 제목·본문·숫자·이름·날짜·장 번호·자리표시 이미지(같은 크기로). 템플릿 예시 문구(영어·중국어)가 남지 않게 한다.
   - **인포그래픽 장**: `python3 $S ig <이름>` 이 주는 조각(`<div class="ms-ig">` + `<script type="text/x-infographic">`)을 헤드라인 아래에 넣고 데이터만 그 장 내용으로 바꾼다. 흐름형 장은 블록(`width:100%; height:560~620px`), 1920x1080 좌표 장(deck-stage)은 `position:absolute` 로 헤드라인과 겹치지 않게. `theme` 블록은 쓰지 않는다(덱 색·서체가 자동). 아이콘은 영어 낱말(`rocket`·`chart line`)로 — 로컬 Tabler 에서 찾는다. 인포그래픽 안의 글도 한 줄 짧게.
   - **직접 그린 도식 장**(2026-10-22 diagram-design 참조 도입): `python3 $S diagram <계열>` 의 장표 규약·배치 문법을 읽고 `<div class="ms-ig" data-ms-diagram="<계열>">` 안에 인라인 SVG 를 새로 그린다. viewBox = 그릇 px · 글자 20px 이상(주 라벨 28~32px) · `font-family` 를 쓰지 않음(덱 서체 — `meta-slide.css` 가 지정) · 색은 `currentColor` 와 강조 `var(--ms-ig-1)` 한두 곳 · 한글 두 줄은 `<tspan>`. 계열마다 장 하나의 상한(벤 3집합·폭포 8막대·레이더 5축·간트 6행 …)을 넘으면 글자를 줄이지 말고 장을 나눈다. 폭포·기울기·트리맵은 문서의 `data-*` 선언을 지킨다. `examples/` 원본은 영문·hex·8~14px 문서용이라 붙여 넣지 않는다.
   - **원칙 적용**: 장마다 헤드라인 하나 · 강조는 핵심 단어만(굵게 또는 포인트 색, 한 장에 한두 곳) · 두 줄이면 핵심 줄만 크게, 세 줄이면 점층(가장 중요한 것 맨 아래, p190~191) · 핵심이 둘 이상이면 도식 · 표는 그래프로, 안 되면 선 최소화 · 간지는 같은 레이아웃에 색만 바꿔 반복(p173) · 허전한 장은 아이콘·실루엣·뒤에 깐 그림(p198).
   - **도식은 장마다 내용 구조에 맞게, 다양하게**(2026-10-23 사용자 「Flow 나 인포그래픽이 맘에 안 들어 — 몇몇 패턴만 반복되고, 다양하게 + 적합한 것을 사용하게」): 흐름·숫자 장을 「가로 상자 4~5개 + 화살표」·「큰 숫자 셋」 같은 한두 틀로 돌려 쓰지 않는다. 먼저 내용의 모양을 정하고 거기 맞는 계열을 `ig`·`diagram` 에서 고른다 — 하나가 여럿으로 퍼짐 → 계층 트리 · 역할이 주고받음 → 스윔레인 상호작용 · 판단 갈림 → 트리·흐름도 · 여럿이 모였다 나감 → dagre 흐름도 · 전체 중 비중 → 원 그래프·트리맵 · 단계가 쌓여 오름 → 오름 계단·레이어 · 되풀이 → 순환 · 두 쪽 → 두 쪽 비교 · 시간 → 타임라인·간트. 사례 덱이면 흐름의 단계마다 실제 화면을 잇는 것도 한 가지 모양이다. 같은 틀은 한 덱에 세 장까지 — `shots` 의 `틀 반복` 이 네 장 이상을 잡는다.
   - **한국어 줄바꿈은 직접 지정**(2026-10-21 사용자 「세 / 미나로」 지적): 제목·카드 문구가 두 줄이면 의미 단위에서 `<br>`. `keep-all` 은 단어 중간 끊김만 막는다.
   - 실제 화면 캡처를 넣으면 개인 이름·사진·약국명 같은 개인정보는 가린다. 사내 공유용이라 가리지 말라는 지시가 있으면 그대로 두되(2026-10-23 사용자 「사내 공유용이라 굳이 화면의 개인정보를 지울 필요 없어」), 공개 범위를 회사 밖으로 넓히기 전에는 다시 확인한다.
9. **`shots --pdf`** — Playwright 로 장마다 1920x1080 캡처, `sheet.png`, `deck.pdf`, `report.json`. 캡처 전에 등장 애니메이션을 끝 상태로 돌린다. 자동 검사: 화면 밖·잘린 글(「01」「26」처럼 두세 글자 장식은 제외), **한글이 고른 서체가 아닌 시스템 서체로 그려진 장**(CDP 실측). **인포그래픽 가독성**: `ig-small`(가장 작은 글자가 1920 캔버스에서 20px 미만) · `ig-overlap`(글끼리 겹치거나 칸을 넘침) — 같은 계열의 다른 모양으로 바꿔 다시 `shots`, 계열 안에 통과하는 모양이 없으면 그 장은 인포그래픽을 빼고 템플릿 어휘로 도식을 그린다(Jev 판정은 그대로 보고에 적는다). plain-text 모양은 desc 를 그리지 않으므로 날짜·설명을 label 에 붙인다. 직접 그린 도식도 같은 `ig-small`·`ig-overlap` 을 받고(`<title>`·`<desc>` 는 제외), 폭포·기울기·트리맵은 `diagram-math`(원본 `verify/` 스크립트로 합계 보존·양쪽 같은 척도·면적=비율 대조)도 받는다 — 걸리면 항목을 줄이거나 값·좌표를 고쳐 다시 그린다. **상자와 글 겹침** `box-overlap`(글이 든 카드 위에 그 카드에 속하지 않은 글이 30% 넘게 걸침 — 10-23 AX 덱 흐름도 갈림 상자 위 결과 줄. 장 번호·화살표 같은 두세 글자 장식과 고정 위치 요소는 제외, 판 안에 통째로 든 글은 판의 글과 부딪칠 때만, 자기 바탕을 깐 이름표·스티커는 디자인으로 보고 뺀다 — 템플릿 전수 QA 4/230종, 모두 꼬리말이 카드에 걸린 실제 겹침). **틀 반복**(같은 부모 아래 같은 꼴로 세 칸 이상 되풀이된 구조와 인포그래픽 계열이 같은 장이 네 장 이상 — 큰 실제 화면 장·글 120자 미만 장(표지·간지·한 문장)은 셈에서 뺀다. 10-23 AX 덱 흐름도 8장 `div.fl>div.nd` 를 잡음) — 걸리면 그 장들을 내용 구조에 맞는 다른 계열로 바꾼다. 통과해도 `sheet.png` 를 직접 보고 강약·도식·자간·인포그래픽 겹침·남은 예시 문구를 확인한다. 고치면 다시 `shots`.
10. **보고 첫 줄**: 시놉시스 전략(있으면) · 템플릿 id·이름 · 색 체계 · 제목/본문 서체 · 장 수 · 인포그래픽 장 수, 각 고른 경로(user·series·jev·default)와 확신도. 그다음 `deck.html`·`deck.pdf`·`sheet.png` 경로. 끝나면 `record`.

공유가 필요하면 `deck.pdf` 를 보내거나, 덱 폴더를 Artifact 로 게시한다(`deck.html` + `files` 에 같은 폴더의 js·css·자산).

## 템플릿·자원 추가

- 인터넷 템플릿: `template.html` + `template.json`(slug·name·tagline·mood·occasion·tone·formality·density·scheme·palette·typography·best_for·avoid_for·source) + 원본 `LICENSE` 를 `data/templates/<접두어>-<slug>/` 에 넣고 `python3 build_index.py <slug>` → `python3 qa_templates.py <slug>`(한글 견본 글로 캡처해 대체 서체·넘침이 0 인지). 16:9·5장 이상·키보드 → 로 넘어감·원격 스크립트 없음·중국어 서체 없음. AGPL 등 사내 재배포가 곤란한 라이선스는 넣지 않는다(op7418/guizang-ppt-skill AGPL-3.0 제외).
- 사내 템플릿은 두지 않는다. 원칙 자료(사내 Keynote PDF)의 바탕·색·서체·장식을 템플릿으로 옮기지 않는다(2026-10-22 사용자 지시 — 그렇게 만든 `cheil-dark-point` 를 뺐다).
- 인포그래픽: AntV 판을 올리면 `build_infographics.py <antv package> <tabler package>` → `qa_infographics.py`(한글 예시로 전부 렌더해 영문 고정 문구·실패 표시).
- 직접 그린 도식: diagram-design 판을 올리면 `build_diagrams.py <저장소>`(계열 목록·`verify-waterfall.py` 패치는 그 파일의 `DIAGRAMS`·`PATCHES`). AntV 에 이미 있는 계열(사분면·순환·피라미드·깔때기·타임라인)은 넣지 않는다.
